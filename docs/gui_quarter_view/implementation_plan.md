# 実装計画：Macroquadによる2Dクォータービュー（2.5Dヘクス戦場＆ギルド司令部GUI）とステップ実行エンジンの実装

## 1. 概要
本フェーズでは、フェーズ1〜6で完成したデータ駆動型シミュレーター、`WorldState` によるゲームループ、およびヘクス空間タクティクスエンジンを基盤として、GUI画面上で1 Tickごとの戦闘進行やギルド運営（養殖・精錬・市場・派遣・GvG）をリアルタイムに操作・観察できる **2.5DクォータービューGUI（Macroquad製）** を構築します。

---

## 2. アーキテクチャ設計判断 (ADR)

### [ADR-009] 戦闘エンジンのステップ実行ステートマシン化と視覚イベント分離
- **コンテキスト**:
  従来の `simulate_spatial_battle` および `simulate_spatial_gvg` は、ループで一気に全Tickを計算し、終了時の結果とスナップショットを返す設計でした。GUIでリアルタイムにアニメーションやダメージポップアップを表示するには、1フレームまたは1 Tickごとに進行可能なステートマシンが必要です。
- **決定**:
  `SpatialBattleSession` を新設し、戦闘中の状態（`HexMap`, `combatants`, `tick`, 勝敗フラグ）を保持。
  毎Tick `step_tick(&mut self) -> Vec<BattleVisualEvent>` を呼び出すことで、1 Tick分の進行と、そのTickで発生した移動・ダメージ・ミス・AoE爆炎・ノックバック・テキストログなどの「視覚イベント」を返却する設計とします。
- **メリット**:
  描画層（Macroquad）は視覚イベントを受け取ってフローティングテキストや斬撃エフェクト、ログウィンドウを描画するだけでよく、ゲームロジックと描画ロジックの完全な関心事分離（SoC）が達成されます。

### [ADR-010] 2.5Dクォータービュー・ヘクス描画と立体建物フットプリント
- **コンテキスト**:
  フェーズ6で実装された `HexCoord::hex_to_pixel`（Y圧縮0.58倍）を活用し、画面中央に美しいアイソメトリック空間を描画する必要があります。
- **決定**:
  1. **ヘクスグリッドタイル**: 六角形（Pointy-topped）の6頂点を計算して描画。マウスカーソル下のヘクスを自動検知（`pixel_to_hex`）してハイライト。
  2. **四角い建物フットプリント**: 通行不可の建物や城壁は、上底の六角形/四角形面と、下方向へ押し出した前面・側面を描画し、陰影（上面明るめ、側面暗め）をつけることで2.5Dの立体感（ブロック状の壁や監視塔）を表現。
  3. **ユニットとHPバー**: 味方（青/緑）、敵（赤/紫）、養殖対象（黄色/王冠）で色分けし、頭上に名前、Lv、HPバー、選択時に射程サークルを描画。

### [ADR-011] 日本語TTFフォント自動探索ローダーとフォールバック戦略
- **コンテキスト**:
  MacroquadはデフォルトではASCII文字しか描画できないため、日本語テキスト（漢字・ひらがな・カタカナ）の描画にはTTFフォントの読み込みが必須です。
- **決定**:
  OS上の代表的な日本語フォントパス候補（Linux/Zorin OSの `/usr/share/fonts/opentype/ipafont-gothic/ipag.ttf`, `/usr/share/fonts/truetype/fonts-japanese-gothic.ttf`, `/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc`、Windowsの `C:/Windows/Fonts/msgothic.ttc` 等）を優先順位順に探索し、最初に読み込めたTTFをMacroquadの `load_ttf_font_from_bytes` でキャッシュ。
  万が一フォントが見つからない場合でも、標準フォントで英語/ASCII表示にフォールバックしてクラッシュを防止します。

### [ADR-012] CUI/GUI共存アーキテクチャ（完全後方互換性）
- **コンテキスト**:
  CIや自動テスト（`cargo test`）、および高速回帰テスト（`cargo run -- --headless-demo`）は、ウィンドウマネージャやX11/Wayland環境のないコンテナやサーバー上でも即座に完走する必要があります。
- **決定**:
  - `main.rs` でCLI引数を解析：
    - `--headless-demo`: 従来の全システム自動回帰テストをCUIで実行
    - `--cli`: 従来のインタラクティブCUI司令部をターミナルで実行
    - 引数なし（または `--gui`）: Macroquadの2Dグラフィカルウィンドウを起動
  - Macroquad依存コードはすべて `src/gui.rs` に集約し、`engine.rs` や `world.rs` には描画クレートの依存を一切持ち込みません。

## 3. 実装計画とファイル構成

1. **`Cargo.toml` の更新**:
   - `macroquad = "0.4"` の追加
2. **`src/engine.rs` の拡張**:
   - `BattleVisualEvent` enum の定義
   - `SpatialBattleSession` 構造体と `step_tick` メソッドの実装
   - 既存の `simulate_spatial_battle` / `simulate_spatial_gvg` を `SpatialBattleSession` を内部利用する形に整理、またはセッション構築ヘルパーを追加
   - ステップ実行の単体テスト追加
3. **`src/gui.rs` の新設**:
   - 日本語フォント探索・ロード
   - クォータービュー描画ヘルパー（六角形描画、建物立体ブロック描画、エフェクト、フローティングテキスト）
   - RO風チャットログパネル（画面左下、スクロール）
   - ギルド司令部操作パネル（再生速度、バトル開始、精錬、市場、派遣、転生、セーブ）
   - メインループ（イベント更新、バトルセッションのTick進行、レンダリング）
4. **`src/main.rs` の更新**:
   - コマンドライン引数に応じたGUI起動 / ヘッドレス起動の分岐
5. **テストと検証**:
   - `cargo test` の実行（全テストパス）
   - `cargo run -- --headless-demo` の完走
   - GUIビルドと起動検証
