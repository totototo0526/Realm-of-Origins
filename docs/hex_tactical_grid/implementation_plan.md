# 実装計画書: ヘクスグリッド空間戦場・A*経路探索・建物フットプリント・射程と陣形タクティクス

## 1. 概要と目的
本フェーズでは、従来の距離概念のない数値シミュレーション型戦闘エンジンから、**ヘクス（六角形）グリッド空間座標、四角い建物のフットプリント（障害物）、A*経路探索、武器・スキルの射程（Range）、範囲攻撃（AoE）、ノックバック、および陣形タクティクス**を備えた空間タクティカルエンジンへと進化させます。
これにより、将来的なクォータービュー（アイソメトリック）2D GUI描画の直接の基盤を確立し、チョークポイント（狭路）での前衛防衛や後衛からの遠距離砲撃、モンスターのノックバック完封など、戦術的なビルド・編成の深みを大幅に拡張します。

## 2. アーキテクチャ設計判断（ADR: Architecture Decision Records）

### ADR-005: ヘクスグリッド座標系（Pointy-Topped Axial ＋ 2.5Dアイソメトリック変換）の採用
- **背景**:
  ヘクス座標系には、Offset（偶数/奇数行ずらし）、Cube（x, y, z; x+y+z=0）、Axial（q, r）の表現がある。また、向きとして Pointy-topped（頂点が上）と Flat-topped（辺が上）がある。
- **決定**:
  1. 内部データ表現として **Pointy-Topped Axial 座標系 (`HexCoord { q: i32, r: i32 }`)** を採用する。
  2. Cube座標の3軸 `(q, r, s)` は `s = -q - r` で即座に導出可能であるため、データ構造体は2つの整数のみ保持し、メモリを節約する。
  3. 距離計算（ヘクス間距離）はCube距離公式を採用：
     `distance(a, b) = (|a.q - b.q| + |a.r - b.r| + |a.s - b.s|) / 2`
  4. クォータービュー（アイソメトリック）2Dスクリーン座標変換：
     Pointy-topped ヘクスは、クォータービュー特有の「横長・斜め見下ろし」と極めて相性が良い。
     - 水平間隔: `x = hex_size * (sqrt(3) * q + sqrt(3)/2 * r)`
     - 垂直間隔: `y = hex_size * (3/2 * r) * ISO_Y_RATIO` (ここで `ISO_Y_RATIO = 0.58` など、Y軸を約60%に圧縮して2.5Dアイソメトリックビューを実現)
- **効果**:
  6方向への対称な移動判定、自然な回転と直線判定、および将来のGUI描画との1対1の数学的整合性が担保される。

### ADR-006: 建物・障害物の矩形フットプリント (`BuildingFootprint`)
- **背景**:
  クォータービューのゲームにおいて、民家、監視塔、防壁、岩などのオブジェクトは「正方形・長方形」のフットプリントを持つことが多い。ヘクスグリッド上に四角い建物を配置した際、自然に通行不可（Blocked）マスクを生成する仕組みが必要である。
- **決定**:
  - `BuildingFootprint` 構造体を導入。原点 `(q, r)` と、Axial軸またはローカル矩形グリッドサイズ `(width, height)`、および障害物タイプ（`Wall`, `Building`, `Rock`）を定義。
  - ヘクス占有マスクを事前計算し、`HexMap` の通行不可セット (`HashSet<HexCoord>`) に登録。
  - これにより、「建物の間の幅1ヘクスの通路（チョークポイント）」や「後衛を隠す建物の陰」を直感的なRONデータから生成可能とする。

### ADR-007: A*経路探索アルゴリズムと「射程内到達」ゴール判定
- **背景**:
  戦闘員（プレイヤーキャラ、モンスター）は、ターゲットヘクスそのものに重なるのではなく、「自身の `attack_range`（射程）以内のヘクス」に到達すれば移動を停止し、攻撃を開始できる必要がある。
- **決定**:
  - `BinaryHeap<AStarNode>` による高速なA*アルゴリズムを `src/hex_grid.rs` に実装。
  - ヒューリスティック関数 $h(n)$ には、ターゲットヘクスまでのヘクスCube距離（Admissible）を使用。
  - 探索の終了条件（ゴール判定）：
    - 通常の経路探索: `current == goal`
    - 戦闘移動経路探索 (`find_path_to_range`): `hex_distance(current, target) <= attack_range` を満たした最初の時点で探索成功。
  - 通行不可条件：建物フットプリントによる障害物ヘクス、および他ユニットが存在するヘクス（味方同士の重なりやすり抜けを防止）。ターゲット自身のヘクスは射程計算の基準点とし、通行不可であってもゴール判定の基準として扱う。

### ADR-008: 空間タクティクス（射程・移動速度・ノックバック・AoE・陣形）とエンジンの統合
- **背景**:
  フェーズ5までの戦闘は同一地点での殴り合いであった。空間戦闘を導入するにあたり、既存のASPDやTickシステムを破壊せずに移動と空間スキルを統合する。
- **決定**:
  1. **移動速度 (`move_ticks`) と `/noctrl` 再現**:
     - キャラクターおよびモンスターに移動間隔（`move_ticks`、AGIが高いほど短い、例: 8〜14 ticks）を追加。
     - 行動可能 Tick において、ターゲットとの距離が `attack_range` より大きい場合、A*で算出した次の1ヘクスへ移動し、`next_move_tick = current_tick + move_ticks` を設定。
     - 射程内に入った瞬間から、ASPDに従った通常攻撃/スキル発動Tick（`next_action_tick`）で連続攻撃を開始（ROの `/noctrl` クリック移動＆自動通常攻撃の再現）。
  2. **ノックバック（突き飛ばし）**:
     - 攻撃者から被攻撃者への方向ベクトルを算出し、被攻撃者を後方へ $N$ ヘクス（例: 2ヘクス）移動させる。
     - 途中に障害物（建物フットプリント）や他の戦闘員がいる場合は手前で停止（壁衝突演出）。
     - 近接攻撃モンスターをノックバックさせると射程外になり、モンスターは再びA*で歩き直す必要があるため、遠距離職による「引き撃ち・完封」が成立する。
  3. **範囲攻撃（AoE: Area of Effect）**:
     - 指定ヘクスおよびその周囲半径 $R$ ヘクス（`get_hexes_in_radius`）内のすべての敵対戦闘員を巻き込み、同時にダメージを与える。
     - ガンビット条件 `Condition::EnemiesInRadius { radius, min_count }` により、敵が集結しているチョークポイントへ自動で【ファイアーボール】等を投下。
  4. **陣形（Formation）とスポーン配置**:
     - チームは初期位置として陣形オフセット（前衛: 最前線, 中衛: 1〜2ヘクス後方, 後衛: 3〜4ヘクス後方）を指定可能。
     - 狭路の前に前衛（VIT壁ナイト）を立たせ、後方の狭路出口から後衛（弓・魔法）が攻撃する戦術配置が可能。
  5. **後方互換性**:
     - 既存の `simulate_battle` および `simulate_gvg_battle` は、デフォルトのオープン戦場マップを自動適用して空間戦闘エンジンで解決するようにリファクタリング。既存の戻り値型（`BattleResult`, `GvgResult`）やフィールドを維持し、すべての既存テストとモードの互換性を完全に保つ。

## 3. 実装モジュール構成
1. `src/hex_grid.rs` (新設):
   - `HexCoord`, `HexDirection`
   - `BuildingFootprint`, `HexMap`
   - `AStar` 経路探索 (`find_path`, `find_path_to_range`)
   - 2Dスクリーン座標変換 (`hex_to_pixel`, `pixel_to_hex`)
   - CUIコンソール用アスキーアート描画 (`render_ascii_map`)
2. `src/models.rs` (拡張):
   - `Equipment` / `Skill` / `MonsterTemplate` / `SpawnedMonster` への `attack_range`
   - `Effect::Knockback { distance }`, `Effect::AreaOfEffect { radius }`
   - `Condition::TargetDistanceAtLeast(u32)`, `Condition::TargetDistanceAtMost(u32)`, `Condition::EnemiesInRadius { radius, min_count }`
   - `Formation` / `TacticalPosition`
3. `src/engine.rs` (拡張):
   - `Combatant` に `position: HexCoord`, `move_ticks: u32`, `next_move_tick: u32`, `attack_range: u32` を追加
   - A*接近、ノックバック、AoE巻き込み、陣形初期化
   - 戦況ログへの盤面スナップショットの記録
4. `src/main.rs` (拡張):
   - `--headless-demo` に空間タクティクス検証シナリオを追加
     1. チョークポイント防衛＆遠距離ハラスメント検証
     2. 空間GvG陣形激突（自軍 vs ライバルギルド）
