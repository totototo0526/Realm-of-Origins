# Implementation Plan: フェーズ2 - 簡易ガンビットと過剰精錬（クホホ工場）の実装

## 1. 概要
獲得したZenyと予備装備を鍛冶屋に投入して限界突破を目指すアイテムシンク機能（ワークオーダー式・過剰精錬）と、敵の個体差（迅速型等）に対応する戦術システム（簡易ガンビット）を実装し、【戦闘 → 資金獲得 → 精錬による装備強化・ロスト → 再挑戦で討伐速度逆転】のコアループを構築・検証します。

## 2. アーキテクチャと詳細設計

### A. 簡易ガンビットシステム (`GambitRule`)
- `Condition`:
  - `TargetArchetypeIs(MonsterArchetype)`: 敵の個体差（例: `Swift` 迅速型）を検知。
  - `SelfHpBelow(f32)`: 自身のHP割合が閾値未満。
  - `Always`: デフォルト。
- `Action`:
  - `UseActiveSkill(String)`: 指定アクティブスキルを実行（例: 必中強撃スキル `bash`）。
  - `SwitchWeapon(String)`: 武器切り替え。
  - `NormalAttack`: 通常攻撃。
- `GambitRule`:
  - `id: String`, `priority: u32`, `condition: Condition`, `action: Action`
- 実行エンジン連携:
  - 行動Tick到来時、優先度の高いルールから順に評価。
  - 敵が迅速型（高FLEE）の場合、ガンビットで `bash`（必中かつ高ダメージ）が発動し、MISSによる時間ロスを完全回避する。

### B. ワークオーダー式過剰精錬 ＆ スロット解放 (`src/refinery.rs`)
- 装備の拡張:
  - `refine: u8` (0〜15), `slots: u8` (最大4), `is_locked: bool` (希少品保護ロック)
- 精錬ボーナス:
  - 基礎ATK上昇: `+1` ごとにATK上昇。
  - 限界突破ボーナス:
    - `+7` 以上: ASPD +5%、クリティカル率 +5%
    - `+10` 以上: 防御力無視ダメージ +100、オートスペル発動確率 2倍
- 成功確率とロスト（クホホ…）:
  - `+1` 〜 `+4`: 100% (安全圏)
  - `+5`: 70%, `+6`: 55%, `+7`: 40%, `+8`: 30%, `+9`: 20%, `+10`: 15%
  - **鍛冶屋シナジー**: 精錬担当者の `(DEX + LUK) / 10`（最大+15%）を成功率に加算。
  - 失敗時: ロックされていない装備は消滅（ロスト）。カードも消滅。
  - 安全装置: `is_locked == true` の装備は破壊リスクのある精錬を自動拒否。
- ワークオーダー (`WorkOrder`):
  - バッチ指示により、所持ベース武器（例: 20本）と資金を使って目標レベル（`+10`）まで全自動精錬。
  - 生き残った最上位武器を納品。

### C. 3ステップ検証シナリオ (`main.rs`)
1. **Step 1: 初期狩り（資金・ベース武器獲得）**
   - パーティーBで10連戦を行い、Overchargeによる資金（Zeny）とベース武器（ダマスカス短剣20本）を準備。
2. **Step 2: 全自動クホホ工場の稼働**
   - DEX/LUK極の鍛冶屋にワークオーダー（目標: `+10`、投入: 20本＋資金）を発行。
   - リアルタイム風の成功・クホホ失敗ログを出力。
   - 生き残った最高精錬値武器（`+9`または`+10`）に特化カード（ヒドラ）＋オートスペルカード（炎眼）を装着し、`is_locked = true`。
3. **Step 3: 強化武器 ＋ 対Swiftガンビットでの下克上再挑戦**
   - アタッカーに過剰精錬武器を装備させ、迅速型対策ガンビット（対Swift -> バッシュ）を設定。
   - 同一10連戦に再挑戦。
4. **比較サマリー（3列）**:
   - パーティーA（脳筋） vs パーティーB（精錬前） vs パーティーB改（過剰精錬＋ガンビット）
   - アタッカー1名が脳筋2名を討伐速度で凌駕する逆転劇を実証。

## 3. 実装手順
1. `src/models.rs` の拡張（ガンビット、装備ロック、スキル仕様拡張）

5. `src/main.rs` の3ステップシナリオ実装
6. `cargo check` & `cargo run` で動作検証
7. `walkthrough.md`, `agent.md`, `README_DEV.md` の更新
